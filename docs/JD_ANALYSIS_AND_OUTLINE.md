## 0. 一句話結論

**現在的網頁大半在介紹 MICH，而不是在證明「你能做這份工作」。**
改版方向：把每一頁換成「我替 MICH 做的一件行銷作品」，每件作品對應職缺的一條職責。
整份簡報的主軸是：**「我已經開始做這份工作了，這是我替 MICH 做的幾件作品。」**

## 1. 職缺在要什麼

MICH 把整套地端 AI 伺服器（硬體、作業系統、數據整合、模型、AI Agent）出貨進客戶機房。
這個職位要把它的價值講給**台灣、美國、日本**三個市場聽懂，
而且**行銷日曆、預算、成效數字都由這個人端到端負責**。

### 職責（依重要性）

| 優先 | 職責 | 實際要交出的東西 |
|---|---|---|
| ★★★ | **1 定位與訊息架構** | 對資安 IT、廠務製造、研發三種決策者的價值主張與疑慮回應；把 LowsiteOS、NVIDIA AI Enterprise、Supermicro 從規格翻成商業成果；三市場三語言一致 |
| ★★★ | **2 內容與數位渠道** | 官網資訊架構、產品頁、案例、白皮書、SEO、雙語內容；LinkedIn 公司頁與經營層 thought leadership；Meta 與區域社群；**AI 輔助的內容生產流程** |
| ★★★ | **3 通路與夥伴行銷** | 銷售支援素材：pitch deck、one-pager、demo 腳本、競品比較、**ROI 模型**；NVIDIA、Supermicro 的 co-marketing 與 MDF；替業務做特定客戶的客製素材 |
| ★ | 4 活動與現場行銷 | 研討會、展會（COMPUTEX、SEMICON Taiwan、GTC）端到端執行 |

| ★ | 6 AI 導入專案 | 支援公司內部 AI 轉型 |

### 必備條件：其實是淘汰門檻，比職責更要先過

1. **英文書面與口語達專業水準**：能獨立產出不需他人潤稿的對外素材，能在全英文會議代表 MICH。
2. **商務寫作清楚精準**：能把技術材料轉成客戶看得懂的文案。
3. **生成式 AI 實務能力**（Claude、Claude Cowork、ChatGPT）：prompt 設計、多步驟工作流程、**產出驗證**。
4. **對企業數據與 AI 基礎架構有興趣**：能說明為什麼製造業堅持把生產數據留在自己機房。

### 加分條件：剛好是你的強項

- 商務日文（JLPT N2）
- **可提供作品集**（帳號、文章、活動、設計、個人專案）
- Figma、Canva、Adobe、影音剪輯
- B2B 科技、硬體、半導體、SaaS 的實習或工作經驗（你沒有，要用作品補）

## 2. 研究結論：作品集網頁怎麼對應職缺才有效

研究方式：用 NotebookLM 收了 20 篇網路來源，加上職缺全文和你的現有網頁，交叉分析（來源清單見文末）。

1. **證據壓過自我宣稱。** 招募主管不會因為「我很會」就相信，要看到成品。
   一個主張沒有證據，就只是意見。
2. **作品集是決策軌跡，不是畫廊。** 每件作品用同一個四段結構：
   **問題**（為誰解決什麼）→ **我的選擇和理由** → **成品**（截圖、文件、可互動的東西）→ **我會怎麼衡量成效**。
3. **新鮮人可以用模擬作品補經驗。** 替真實品牌做的提案、審計、模擬活動都算，
   只要**誠實標示**「這是我依公開資料自製的提案，不是 MICH 官方素材」。
4. **AI 能力要展示流程，不要只說「我會用」。** 說法應該像：
   需求說明 → AI 產出多個版本 → **我挑選並說明理由** → 驗證事實 → 修正。
   重點是講清楚**哪些判斷是人做的**。
5. **現場簡報要精不要全。** 主線只放最能打的 3 件左右作品，深入講；
   其餘放附錄，被追問時再翻出來。
6. **數字只用查得到出處的。** 保守、具體的說法比漂亮的大數字可信。
   不要寫「排程優化 50%」這種沒人量測過的數字。

### 作品①「決策者訊息表」每一欄要寫什麼

參考 GTM Playbook 的 persona messaging matrix，每種決策者都要填滿這幾欄，缺一欄業務就只能自己即興：

| 欄位 | 寫什麼 |
|---|---|
| 角色 | 具體職稱（例如 CISO、廠長），不要寫「IT 人員」 |
| 主要痛點 | **一個**，他最被追究責任、而 MICH 能解決的事 |
| 他眼中的成功 | 他自己怎麼定義做得好 |
| 主打的訊息重點 | 三個重點裡，哪個最直接回應他的痛點 |
| 證據 | 同類角色的案例或數字，越具體越好 |
| 最常見的反對意見 | **一個**，最常讓這類人說不的那句話 |
| 回應話術 | 寫成業務看一次就能照講的句子 |

### 幾個判斷（為什麼這樣排）

- **「補強」不要單獨一頁。** 一整頁講缺點等於提醒面試官風險；併進 90 天那頁，改寫成計畫。
- **夥伴行銷提案放附錄。** 新鮮人講 MDF、預算分配容易說超過自己懂的範圍，被問到再翻出來。
- **開場就預告「今天給您看三組作品」**，讓面試官知道接下來要看什麼。
- **收尾只留一句話和聯絡方式**，不要再塞資訊。

## 5. 改版守則

1. **所有數字要有出處。** MICH 的數字來自 MICH 官網；薪資來自 104、厚生勞動省、美國 BLS。查不到的不要寫。
2. **自製作品要標示清楚。** 例如在作品角落加「依 MICH 官網公開資料自製提案」。
3. **作品①～④要你自己能講。** AI 可以幫你起草，但面試官會追問「為什麼這樣選」，那個答案只有你能給。
4. **經歷只寫真的。** 世田谷區公所、松江 LEXUS 的細節由你補，不要讓 AI 幫你編。
5. **英文版要你自己讀過一遍。** 職缺要求「不需他人潤稿」，面試官可能直接請你用英文講一頁。

## 6. 怎麼改 `index.html`

- **每一頁是一個 `<section class="slide">`**，`id` 是 `s-xxx`。加頁就複製一個 section。
  每個 section 的 `data-title`、`data-title-en`、`data-title-ja` 是目錄和側邊圓點顯示的名稱。
- **文字三語並列**：每段文字寫成
  `<span data-l="zh">中文</span><span data-l="en">English</span><span data-l="ja">日本語</span>`，
  頁面只會顯示目前選的語言。
- **卡片**用 `<article class="card glass">`；排版用 `grid c2`、`grid c3`、`grid c4`（2、3、4 欄）。
- **一頁要放得進一個畫面**（筆電大約 760px 高）。放不下就拆頁或刪字，不要縮字。

### 面試時的操作（你背對螢幕時）

| 按鍵 | 作用 |
|---|---|
| ↓ → 空白鍵 / ↑ ← | 下一頁 / 上一頁 |
| **1～9** | 直接跳到第幾頁（先背好頁碼） |
| **M** | 開關目錄；目錄裡用 ↑↓ 選、Enter 跳過去 |
| Esc | 關閉目錄 |
| Home / End | 第一頁 / 最後一頁 |
